# AI + MCP 应用方案

## 当前能力

当前产品已经具备一个清晰、结构化的动作：

> 根据日期、证券和目标文件类型，从网盘在线压缩包中按需提取历史 CSV。

这类动作非常适合进一步包装成 AI 可调用工具。

## 可怎样封装为 MCP

未来可以把“提取任务”封装成 MCP 工具，让 AI 负责理解自然语言，MCP 工具负责执行确定性的取数动作。

~~~mermaid
sequenceDiagram
    participant U as 用户
    participant A as AI
    participant M as MCP 提取工具
    participant N as 网盘压缩包

    U->>A: 我要 2024-05-20 的 000001 十档行情
    A->>A: 解析日期 / 证券 / 数据类型
    A->>M: 请求目标文件
    M->>N: 按规则定位并提取
    N-->>M: 行情.csv
    M-->>A: 返回目标文件
    A-->>U: 文件 + 后续分析
~~~

## 自然语言示例

~~~text
我要 2024-05-20 的 000001 十档行情。
~~~

~~~text
提取 2023-12-08 的 600519 逐笔成交。
~~~

~~~text
给我 2024-06-18 的 300750 逐笔委托。
~~~

AI 可以将请求规范化为类似：

~~~text
date = 20240520
security = 000001
file = 行情.csv
~~~

## 边界

本仓库**没有宣称已经交付生产可用的 MCP 服务**。这里描述的是基于现有按需提取能力的扩展方向和应用方案。

真正落地 MCP 时仍需要对工具接口、任务状态、错误返回、权限边界和文件交付方式进行工程化封装。
